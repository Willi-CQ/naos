# Project surfaces

Open a planet with a double click in the scene, on its label or in the Manifest. `P` opens the field atlas; **Open surface & chat** opens its selected world. **View orbit** returns to the 3D view. Closing a surface leaves its agents running.

Each project has two permanent views: **Project surface** and **Agents**. The surface combines a landscape with a project inspector; the agent view centers the conversation and places statistics, observed agent relationships and activity on the right. On phones these panels follow their main view vertically. Switching views retains the draft and selected conversation. `L` opens directly into Agents. The project selector changes worlds without changing IDEs.

The header's maximize control uses the full application viewport and restores the previous layout on a second click. The chat's focus icon or `/focus` temporarily hides telemetry and gives the conversation its full width, retaining the inspected agent while pausing its trace polling. Repeating the action restores telemetry. The message editor starts compact, grows with its content and follows window resizing. Its expand icon or `/expand` opens a taller writing area. Layout changes preserve the draft, conversation and stream. Hidden map and telemetry controls are omitted from the dialog's keyboard focus loop.

## Geography

`world.survey` is an authenticated, UI-only command. It resolves a known world ID on the kernel; the caller cannot supply a filesystem path. The bounded asynchronous scan reads directory entries, never file contents. Hidden entries, dependencies, build output and symbolic links are omitted. Workspace packages become individual regions. A seeded coastline and clipped Voronoi territories form a continuous continent. Each territory represents a real project folder, with its name, type and observed file count. Surface and Relief are the two map layers. Terrain and area sizes are illustrative, not dependency or code-size measurements. The original generated terrain asset and prompt are documented in [maps/README.md](../packages/ui/public/maps/README.md).

The scan stops after 6,000 files, 15,000 entries, six directory levels or approximately two seconds of traversal and marks partial results. The map shows up to twelve regions; every region remains available in the searchable inspector directory, including a type filter. Selecting a region outside the first twelve brings it into the map. Selection shows sampled filenames, supports copying its relative path and carries that path into the next conversation. Surveys are cached per world in window memory. Refresh updates that project's cache; an unsuccessful refresh identifies the retained survey.

The inspector shows only the selected project's file and territory counts, observed languages and live agents. Brain, Architecture and the Codex/Claude Code/Cursor workspace are direct integrations with this project. Agent rows open their actual conversation. The global atlas remains a separate project picker; its constellation never appears inside a project surface. Survey results, selections and graph lenses carry their world ID. Switching worlds clears the lens and context immediately, and late responses from another project are ignored. Veiling also hides directory search text, paths, agents and terrain and stops project reads.

## Graph widgets

Brain and Structure open focused widgets over the map, with search, pan, zoom, node selection, an inspector and expansion. Escape closes the widget first and restores focus to its trigger. A selected node can become context for a conversation. The Structure graph shows real folders and sampled filenames from the survey; its lines mean containment.

On narrow screens, opening a graph from the inspector first returns the map's scroll container to the top so the widget appears in view.

`world.knowledge` is a separate authenticated UI-only read, invoked only when opening Brain. It resolves a known world ID and reads Markdown notes under brain, .brain, knowledge, memory, notes, docs, wiki, research and concepts, plus the root README. Wiki links and relative Markdown links between discovered notes form graph edges. Ambiguous wiki names, absent targets, external URLs, paths escaping the project, dependencies, hidden secrets and symbolic links are omitted. Only relative paths, document titles and edges return to the UI. Bodies never enter events or logs.

The knowledge scan stops at 160 documents, 8,000 directory entries, 2 MB of text or approximately 1.8 seconds; individual files are at most 64 KB and traversal is at most five levels. Limits and unreadable files mark a partial graph. Empty projects show guidance. A veil unmounts the widgets and ignores any late read result.

## Agent telemetry

The right pane includes active-agent and subagent counts, observed output tokens and token rate, a connection diagram, the complete agent tree, a recent project activity feed and selected-agent details. Its Live trace tab follows the selected agent's turns, reported reasoning stages, responses, tool calls and failures in timestamp order. File read/edit targets appear when the provider reports them; command arguments stay summarized. The Changes tab lists the selected project's Git working-tree changes, staged state and line counts, then loads a bounded diff only for the selected changed file. Untracked files receive add-file previews. Paths stay project-relative, and Veil stops and clears Git reads. Running tools pulse in place, and completed tools show their observed status. The tree preserves every observed descendant, including ended agents and descendants hidden by the universe's client filter. It uses an iterative traversal with cycle protection; missing parents do not discard nodes. Deep rows retain their actual level, with bounded visual indentation.

Selecting a subagent inspects its model, context and tool trace without changing the conversation. Main agents can open their conversation. The selected trace refreshes through `craft.channel` while the agent view is open and stops on privacy veil, disconnect or close. Provider telemetry determines the available detail: unreported context or tool activity is identified as such. The connection diagram animates reported live nodes; it does not fabricate agent locations or tasks.

Native tool notifications now update one trace row per tool ID. Duplicate running updates do not count as additional calls. Completion and failure update the row and publish structural tool/activity events into the project feed. Durations use the locally observed start and completion times; a completion without a start has an unknown duration. Codex item completion follows the [official OpenAI App Server documentation](https://learn.chatgpt.com/docs/app-server#items), reviewed 2026-11-04. Cursor retains the documented ACP tool-call lifecycle. Token counters show only reported data.

## Conversations

The chat uses `agent.providers`, `preflight`, `agent.spawn`, `agent.send`, `craft.text` and `craft.watchText`. Its compact header selects a conversation and shows the project root and current folder focus. One writing surface contains the message, an optional removable context chip, quiet configuration buttons and Send. Healthy provider connections need no separate card; missing CLIs and sign-in problems retain their setup, copy and recheck controls. The conversation owns the remaining height, without launch banners or prompt cards. The latest owned conversation in the project opens by default after a reload; a deliberate `/new` selection still opens a fresh conversation.

Type `/` or click the slash button to open the local command menu. Arrow keys select, Enter applies and Tab completes; Escape closes the menu before the workspace. `/provider` chooses Codex, Claude Code or Cursor; `/model` lists the returned model catalog; `/mode` offers Build, Plan first and Read only. `/codex`, `/claude`, `/cursor`, `/build`, `/plan` and `/read` are aliases. `/skill` searches installed shared, Codex and Claude skills plus Claude and Cursor project commands. Project workflows appear only after the project is trusted; metadata is listed first and instructions are read only after selection. A selected workflow follows the prompt into the provider session and stays hidden in the readable transcript. `/new`, `/sessions`, `/focus`, `/expand`, `/context` and `/help` manage the conversation and layout. `/context` removes the selected project path. `/stop` opens the existing human confirmation; it does not stop an agent directly. Provider, model and mode changes apply to new conversations. Existing conversations keep their provider settings.

Commands run locally and are never sent as inference prompts. A message following the command's first line is retained as a draft. Unknown commands stay local; a leading `//` sends a literal slash to the provider. Clicking Send with a normal message explicitly sends that message, including when the command menu was opened manually. Privacy hides the menu and preserves its underlying draft in window memory.

New conversations default to Codex through the providers' local protocols. Claude Code uses the existing local Agent SDK harness; Codex uses App Server and Cursor uses ACP. Native account limits and permission behavior remain provider-specific. Launches have idempotency keys and an immediate submission lock. Every sent message carries a compact context note with the project name and relative focus path; the UI renders it as a small scope badge rather than repeating it in the visible message. The provider still receives the selected project's root as its working directory, so the folder is a focus hint and never a sandbox boundary. Codex's App Server reports loaded instruction sources when available, and the chat shows only their count. The full user message history remains owned by the provider session and kernel transcript; drafts remain in window memory and unsent drafts are cleared on reload. This creates a project-scoped native session and does not attach to or import an IDE's already-open conversation. See [NATIVE-AGENTS.md](NATIVE-AGENTS.md) for provider, authentication and policy boundaries.

Assistant output supports headings, lists, quotes, tables, inline formatting and fenced code. Code blocks and complete responses can be copied. Rendering never interprets model output as HTML, and links are limited to HTTP(S).

Messages stream over the existing WebSocket; completed transcripts refresh on demand while the selected chat is open. Pending node IDs wait for session initialization before reading text. Only one transcript request runs at a time. Late responses are ignored after switching conversation, changing project, veiling or closing the workspace. Drafts, pending bubbles and the last selected conversation stay in window memory, never localStorage. Completed conversation history belongs to the kernel's transcripts. Reloading the page clears unsent drafts.

Managed native conversations support queued follow-ups, the existing stop control, resume and the human approval docket. Budget increases apply to legacy Claude agents only. Conversations observed from other clients remain read-only. A privacy button hides messages and project paths, disables input and stops transcript and survey reads.

## Verification

`npm run e2e:project` uses the fixture kernel and headless Edge. It checks desktop, compact and mobile layouts, map controls, territory context on launch and follow-up messages, preflight and duplicate launch prevention, project isolation, retained drafts, privacy, external clients and the approval docket. The agent hierarchy, live trace, project change review, installed workflow picker and provider selection are checked independently. It creates no real model calls. Screenshots and reports are under `.shots/project/`.

The `agent-sizing-*` cases verify maximize and restore, chat focus, editor expansion, visible send controls, retained drafts and keyboard focus at 1600 × 1000, 1024 × 768 and 390 × 844. Measurements wait for the window's opening animation to finish; each report records the initial, maximized and restored bounds.

`minimal-chat-*` measures the compact empty editor and available conversation space on those three viewports. `chat-slash-commands` checks keyboard and pointer selection, provider/model/mode routing, following-line drafts, privacy, escaped messages and explicit stop confirmation. `chat-commands-mobile` and `chat-commands-short` verify the menu's viewport bounds and active accessibility target with both compact and expanded editors. A menu that cannot fit above the expanded editor opens over its writing area. Pure command tests cover aliases, literal messages and exact matches taking precedence over descriptive text.

`packages/kernel/test/core/survey.test.ts` and `knowledge.test.ts` cover bounded traversal, Markdown resolution, workspace grouping, link and hidden-entry exclusions, known-world resolution, authentication and UI scope. `packages/ui/test/core/agentTree.test.ts` checks 90 nested levels, cycles and missing parents. Browser tests cover graph widgets, context handoff, view switching, complete agent hierarchy, activity and privacy. Build and typecheck cover all three packages.

`cartography.test.ts` checks a complete map partition, finite boundaries and stable placement when selecting a folder beyond the twelve-territory limit. The `project-data-isolation` browser case supplies distinct project surveys and delayed replies to verify project switching, graph isolation, search, relative-path copy, context handoff and the veil.
